# DEK（数据加密密钥） / Data Encryption Key

> 上次更新：2026-06-29

## 基本信息 / Basic Information

| 字段 Field | 值 Value |
|------------|----------|
| **全称** | Data Encryption Key |
| **类型 Type** | 密钥层次中的底层密钥 / Bottom-layer key in key hierarchy |
| **用途 Purpose** | 直接加密业务数据 / Directly encrypts business data |
| **保护方式** | 由 KEK 加密后存储 / Stored after encryption by KEK |


## 概述

DEK 是密钥层次中最接近业务数据的层级，直接用于加密用户数据、文件、数据库字段等。与 KEK 相比，DEK 的生命周期较短，通常随加密数据一起存储。

```
KEK（加密）─▶ DEK ─▶ 加密数据（与 DEK 一起存储）
                   ↓
              明文 DEK 仅存在于内存中
```

## 密钥层次结构 / Key Hierarchy

| 层级 Level | 名称 Name | 生命周期 Lifecycle | 存储位置 Storage | 典型用途 Use Case |
|-----------|----------|------------------|----------------|-----------------|
| L1 | Root Key | 数年~数十年 / Years~decades | HSM/TPM | 签名根证书 / Root signing cert |
| L2 | KEK | 数月~数年 / Months~years | HSM/软件 / HSM/Software | 加密 DEK / Encrypt DEK |
| L3 | DEK | 数小时~数月 / Hours~months | 内存/缓存 / Memory/Cache | 加密业务数据 / Encrypt business data |


## DEK 的生成方式 / DEK Generation Methods

| 方式 Method | 说明 Description | 适用场景 Use Case |
|-----------|----------------|-----------------|
| **KMS 生成** / KMS-generated | 由 KMS 生成，返回加密后的 DEK / Generated by KMS, returns encrypted DEK | 高安全要求 / High security |
| **应用生成** / App-generated | 应用本地生成，导入 KMS 管理 / Generated locally, imported to KMS | 性能敏感 / Performance-sensitive |
| **EFS 自动生成** / EFS-auto | 文件系统自动管理，每个文件一个 DEK / FS auto-manages, one DEK per file | 文件加密 / File encryption |
| **数据库列级** / DB Column-level | 每个加密列一个 DEK / One DEK per encrypted column | 数据库加密 / Database encryption |


## 在 Envelope Encryption 中的角色

```rust
// DEK 加密流程 / DEK encryption flow
// 对应代码: kms-core/src/envelope.rs
// Corresponding code: kms-core/src/envelope.rs

use kms_core::envelope::{Envelope, generate_dek, generate_nonce};
use kms_core::kek::KEKManager;

struct EnvelopeEncryption {
    kek_manager: KEKManager,
}

impl EnvelopeEncryption {
    async fn encrypt_data(&self, plaintext: &[u8]) -> Result<Envelope, KmsError> {
        // 1. 生成 DEK（国密 SM3 HMAC_DRBG）
        //    Generate DEK (GM SM3 HMAC_DRBG)
        let dek = generate_dek(32); // AES-256 / SM4

        // 2. 使用 DEK 加密数据（SM4-GCM）
        //    Encrypt data with DEK (SM4-GCM)
        let nonce = generate_nonce(12);
        let (ciphertext, tag) = sm4_gcm_encrypt(plaintext, &dek, &nonce)?;

        // 3. 使用 KEK 加密 DEK
        //    Encrypt DEK with KEK
        let (wrapped_dek, dek_nonce) = self.kek_manager.encrypt_dek(&dek).await?;

        Ok(Envelope::new(
            wrapped_dek,
            dek_nonce,
            ciphertext,
            nonce,
            tag,
            self.kek_manager.version(),
        ))
    }
}
```

## DEK 的轮换策略 / DEK Rotation Strategies

| 策略 Strategy | 说明 Description | 优点 Pros | 缺点 Cons |
|--------------|----------------|----------|----------|
| **定时轮换** / Scheduled | 固定时间间隔（如每天）/ Fixed interval (e.g., daily) | 简单可控 / Simple and controllable | 可能中断业务 / May interrupt business |
| **按用量轮换** / Usage-based | 达到使用次数阈值后轮换 / Rotate after usage threshold | 均衡负载 / Balanced load | 复杂实现 / Complex implementation |
| **主动轮换** / Manual | 手动触发，配合数据迁移 / Manual trigger with data migration | 灵活 / Flexible | 需要应用配合 / App cooperation needed |
| **无感轮换** / Seamless | 使用 DEK 版本，渐进迁移 / DEK versioning with gradual migration | 无停机 / No downtime | 实现复杂 / Complex to implement |


## DEK 版本管理

```rust
// DEK 版本状态机 / DEK version state machine
// 对应代码: kms-core/src/key.rs
// Corresponding code: kms-core/src/key.rs

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum KeyStatus {
    Active,          // 可使用（加密/解密）/ Can use (encrypt/decrypt)
    PendingDeletion, // 待删除（仅解密）/ Pending deletion (decrypt only)
    Obsolete,        // 已淘汰（不可使用，保留用于审计）/ Obsolete (not usable, kept for audit)
    Destroyed,       // 已销毁（密钥材料已清零）/ Destroyed (key material zeroized)
}

// 状态转换 / State transitions
//
//      ┌─────────┐
//      │  Active  │◀───────┐
//      └────┬────┘        │
//           │ delete      │ rotate
//           ▼             │
//      ┌─────────────┐   │
//      │Pending      │───┘
//      │Deletion     │
//      └──────┬──────┘
//             │ grace period ended
//             ▼
//      ┌─────────┐
//      │Obsolete │
//      └────┬────┘
//           │ destroy
//           ▼
//      ┌───────────┐
//      │ Destroyed │
//      └───────────┘
```

| 状态 Status | 可加密 Encrypt | 可解密 Decrypt | 可轮换 Rotate | 说明 Description |
|-------------|---------------|---------------|---------------|-----------------|
| Active | ✅ | ✅ | ✅ | 正常使用中 / In normal use |
| PendingDeletion | ❌ | ✅ | ❌ | 待删除，宽限期内仍可读 / Pending, readable during grace period |
| Obsolete | ❌ | ❌ | ❌ | 已淘汰，不可使用 / Obsolete, not usable |
| Destroyed | ❌ | ❌ | ❌ | 已销毁，密钥材料清零 / Destroyed, key material zeroized |

## 安全注意事项 / Security Considerations

1. **内存保护** / Memory Protection：DEK 在内存中应受保护（mlock/seal），防止 swap 写出 / DEK in memory should be protected (mlock/seal), prevent swap-out
2. **及时销毁** / Prompt Destruction：使用完毕后立即清零内存 / Zeroize memory immediately after use
3. **使用计数** / Usage Count：监控 DEK 使用次数，达到阈值后轮换 / Monitor DEK usage count, rotate on threshold
4. **版本隔离** / Version Isolation：旧版本 DEK 保留用于解密历史数据 / Retain old DEK versions for historical decryption
5. **泄露响应** / Breach Response：发现泄露时立即销毁 DEK 并重加密数据 / Immediately destroy DEK and re-encrypt data on breach


## 与 KEK 的对比 / KEK Comparison

| 特性 Feature | KEK | DEK |
|-------------|-----|-----|
| **层级** / Layer | L2 | L3 |
| **用途** / Purpose | 保护 DEK / Protects DEK | 加密业务数据 / Encrypts business data |
| **生命周期** / Lifecycle | 长 / Long | 短 / Short |
| **存储位置** / Storage | HSM | 内存/缓存 / Memory/Cache |
| **轮换频率** / Rotation | 低 / Low | 高 / High |
| **数量** / Quantity | 少（按用途/租户）/ Few (by purpose/tenant) | 多（按文件/记录）/ Many (by file/record) |
